# Flamingo County — route map

One file per route. Every nav destination is its own page (its own document, its own URL,
its own data resolution) — no client-side screen switching.

| Design file | Next.js App Router path | URL params here | Server work in Next.js |
| --- | --- | --- | --- |
| `Home.dc.html` | `app/[lang]/page.tsx` | `?city=&cat=&q=` | Search + category/city filtering runs on the server; `searchParams` drive the query. Spotlight picked server-side. |
| `City.dc.html` | `app/[lang]/[city]/page.tsx` | `?city=` | `generateStaticParams` over the three cities; per-city listing counts, stats and picks. `generateMetadata` per city. |
| `Business.dc.html` | `app/[lang]/[city]/[business]/page.tsx` | `?city=&biz=` | Listing record + story + menu/services fetched server-side. `generateMetadata` (title, description, OG image) per listing. |
| `Events.dc.html` | `app/[lang]/events/page.tsx` | `?city=&kind=&view=&month=` | Filters, buckets (this weekend / next week / later) and the month grid are computed server-side from the params. |
| `Event.dc.html` | `app/[lang]/events/[slug]/page.tsx` | `?e=` | Event record + same-day events; ICS is generated by a route handler (`app/api/events/[slug]/ics/route.ts`). |
| `MyWeek.dc.html` | `app/[lang]/my-week/page.tsx` | — | Saved/going state is per-user: cookie or session read on the server, `localStorage` in this prototype. |
| `Stories.dc.html` | `app/[lang]/stories/page.tsx` | — | Story index, statically generated. |
| `Story.dc.html` | `app/[lang]/stories/[slug]/page.tsx` | `?s=` | `generateStaticParams` over story slugs; article metadata + OG. |
| `ListYourSpot.dc.html` | `app/[lang]/list-your-spot/page.tsx` | — | Form POSTs to a server action / `app/api/listings/route.ts`. |
| `About.dc.html` | `app/[lang]/about/page.tsx` | — | Static. |

## Shared layout

| Design file | Next.js equivalent |
| --- | --- |
| `Nav.dc.html` | `app/[lang]/layout.tsx` header (server component; the dropdown/burger/tooltips are one small client child) |
| `Footer.dc.html` | same layout footer; newsletter form is a client island posting to `app/api/subscribe/route.ts` |
| `fc-data.js` | `lib/` — `data.ts` (cities, listings, events, stories), `i18n.ts` (the EN→ES dictionary + `T()`), `ics.ts`, `hrefs.ts` |

## Locale

`?lang=en|es` here maps to the `/[lang]` segment in Next.js (`/es/eventos` style paths if you
want translated slugs). The language choice also persists per device, and every internal link
carries the current locale.

## Notes on this prototype

- Links are real `<a href>` navigations, so filters, search, calendar month and view are all
  URL state — the same shape a server component reads from `searchParams`.
- Saved events / going counts stay client-side (`localStorage`) until there are accounts.
- The old single-page build is kept at `Flamingo County.dc.html` for reference.
